    寻找小于N的最大数#

    题目：

    给定一个整数数组 nums，里面仅包含 0-9 的数字，再给定一个整数 k，求 nums 能组成的小于 k 的最大数。每个数字可以使用任意次数。

    示例 1

    nums = [4, 3], k = 433
ans = 344

    示例 2

    nums = [1, 0], k = 100
ans = 11

    分析：

    一、与 902 题的对比#

    这道题和 902. 最大为 N 的数字组合 非常相似，但有两点关键区别：

    902 题本题
    目标求个数（计数）求最大数（构造）
    条件≤ n（小于等于）< k（严格小于）
    输入digits 为字符串数组nums 为整数数组
    核心方法数学计数 / 数位 DP贪心 + 回溯构造

    902 是「有多少个」，本题是「最大的那个是谁」。前者是 DP 计数问题，后者更贴近回溯搜索。

    二、核心思路：寻找「降级点」#

    要让结果小于 k 且尽可能大，策略是：结果的前缀尽量和 k 相同，在某个位置"降级"（选一个比 k 对应位更小的数字），之后全填最大数字。

    以 nums=[4,3], k=433 为例：

k  =  4   3   3
        ↓   ↓   ↓
位0: 选'4'（等于k[0]），继续
位1: 选'3'（等于k[1]），继续
位2: 选'3'（等于k[2]），但 433 不 < 433 ✗
     没有比'3'更小的数字可选，回溯！

     回退到位1：能选比'3'更小的数字吗？nums 中没有 → 继续回溯
     回退到位0：能选比'4'更小的数字吗？有！'3' < '4'
             后面全填最大数字'4' → 344 ✓

    形式化地说，我们从右向左枚举降级点 p：

    • 位置 p 选一个严格小于 k[p] 的最大数字
    • 位置 0~p-1（前缀）必须和 k 完全相同（保证结果尽量接近 k）
    • 位置 p+1~末尾 全部填 nums 中的最大数字（保证后缀尽量大）

    对所有合法的 p 构造候选值，取其中的最大值。如果没有任何合法候选（比如 k=2 而 nums=[2]），则返回到少一位全填最大数字的情况。

    三、决策树视角#

    以 nums = [1, 5, 9], k = 555 为例：

                            ┌─────────────────┐
                        │   构造 < 555 的数  │
                        │   k = "555", m=3 │
                        └────────┬────────┘
                                 │
            ┌────────────────────┼────────────────────┐
            │                    │                    │
   ┌───────▼──────┐    ┌───────▼──────┐    ┌───────▼──────┐
   │ 降级点 p = 2  │    │ 降级点 p = 1  │    │ 降级点 p = 0  │
   │ 前缀="55"    │    │ 前缀="5"     │    │ 前缀=""      │
   │ 要 < '5'     │    │ 要 < '5'     │    │ 要 < '5'     │

最大: 551 ← 降级点越靠右，结果越接近 k

    关键洞察：降级点越靠右（越低位），结果越接近 k，也就越大。所以从右向左扫描，第一个合法降级点就能给出最优答案——前提是该位置的前缀每一位都在 nums 中。

    如果所有位都无法降级（nums 中没有足够小的数字来组成与 k 等长的数），则退而求其次：构造一个少一位的、全部由最大数字组成的数。例如 nums=[9], k=100 → 两位全填 9 → 99。

    四、Go 实现#

    // date 2025/06/24
func findMaxNumber(nums []int, k int) int {
    sort.Ints(nums)
    s := strconv.Itoa(k)
    m := len(s)
    maxDigit := nums[len(nums)-1]

    // 快速查找：某数字是否在 nums 中
    has := make(map[byte]bool)
    for _, d := range nums {
        has[byte('0'+d)] = true
    }

    best := -1

    // 从右向左枚举降级点 p
    for p := m - 1; p >= 0; p-- {
        // 找 nums 中小于 s[p] 的最大数字
        largestLess := -1
        for _, d := range nums {
            if byte('0'+d) < s[p] && d > largestLess {
                largestLess = d
            }
        }
        if largestLess == -1 {
            continue // 这一位无法降级，跳过
        }

        // 检查前缀 s[0..p-1] 的每一位是否都在 nums 中
        validPrefix := true
        for j := 0; j < p; j++ {
            if !has[s[j]] {
                validPrefix = false
                break
            }
        }
        if !validPrefix {
            continue
        }

        // 构造候选数字
        candidate := make([]byte, m)
        for j := 0; j < p; j++ {
            candidate[j] = s[j] // 前缀与 k 完全相同
        }
        candidate[p] = byte('0' + largestLess) // 降级点，取小于 k[p] 的最大数字
        for j := p + 1; j < m; j++ {
            candidate[j] = byte('0' + maxDigit) // 后面全部填最大数字
        }

        val, _ := strconv.Atoi(string(candidate))
        if val < k && val > best {
            best = val
        }
    }

    // 兜底：少一位，全填最大数字
    if m > 1 && maxDigit > 0 {
        candidate := make([]byte, m-1)
        for j := 0; j < m-1; j++ {
            candidate[j] = byte('0' + maxDigit)
        }
        val, _ := strconv.Atoi(string(candidate))
        if val < k && val > best {
            best = val
        }
    }

    // 极端情况：只有数字 0 可用，且 k > 0
    if best == -1 && has['0'] && k > 0 {
        return 0
    }

    return best
}

    五、代码要点说明#

    1. 为什么从右向左枚举降级点？

    降级点越靠右，结果的前缀和 k 相同的位数越多，结果越接近 k（也就越大）。从右向左找到的第一个合法降级点产生的候选就是最优的。不过由于需要检查前缀合法性，我们仍然遍历所有 p 并取 max。

    2. 前缀合法性检查

    降级点 p 意味着位置 0 到 p-1 必须和 k 的对应位完全相同。如果 k 的某一位不在 nums 中，那么以该位置为分界的所有降级点（包括更靠右的）都是无效的。比如 k=250, nums=[2,5]：k[1]=‘5’ 在 nums 中，但 k[2]=‘0’ 不在，所以 p=2 的前缀 “25” 合法，但 p=1 的前缀 “2” 也合法（p 更小，前缀更短）。实际上，p=1 的前缀只到 k[0]=‘2’，它在 nums 中，所以 p=1 合法。

    3. 为什么最后要处理 maxDigit=0 的情况？

    当 nums 中只有 0 时（如 nums=[0]），maxDigit=0，少一位全填 0 的结果还是 0。这种情况单独处理：只要 0 在 nums 中且 k>0，0 就是合法答案。

    4. 关于前导零

    构造候选时，如果第一位是 ‘0’（比如 nums=[0,1], k=100 中降级点 p=0 选 ‘0’），候选字符串是 “011”。strconv.Atoi("011") 会正确解析为 11。前导零被自动处理，结果是一个更短的数字，这在逻辑上是正确的（数字 011 = 11）。

    5. 返回 -1 的含义

    当没有任何合法数字 < k 时返回 -1。例如 nums=[2], k=2：唯一能组成的数字是 2，但它不小于 2。

    六、复杂度分析#

    • 时间复杂度：O(m × n)，其中 m 是 k 的位数（≤10），n 是 nums 的长度（≤10）。实际上 m 和 n 都很小，几乎是常数时间。
    • 空间复杂度：O(m + n)，用于存储候选字符串和哈希集合。

    七、回溯视角的两种实现#

    本题虽然可以用贪心算法高效解决，但它的思考过程天然是回溯的。下面给出两种不同思路的回溯实现。

    方法一：逐位决策 DFS（tight/free 状态机）#

    这种写法和 902 题数位 DP 同构。按位递归，用 tight 标记当前前缀是否与 k “紧贴”，从大到小尝试数字，找到的第一个合法结果就是答案：

    // 逐位 DFS —— 与数位 DP 同构，O(m×n)
func findMaxNumberDFS(nums []int, k int) int {
    sort.Ints(nums)
    s := strconv.Itoa(k)
    m := len(s)

    var ans int
    var dfs func(pos int, tight bool, path []byte) bool
    dfs = func(pos int, tight bool, path []byte) bool {
        if pos == m {
            val, _ := strconv.Atoi(string(path))
            if val < k {
                ans = val
                return true
            }
            return false
        }
        // tight 为 true 时，当前位不能超过 s[pos]
        limit := byte('9')
        if tight {
            limit = s[pos]
        }
        // 从大到小尝试，第一个合法结果即最大
        for i := len(nums) - 1; i >= 0; i-- {
            d := byte('0' + nums[i])
            if d > limit {
                continue
            }
            path = append(path, d)
            nextTight := tight && (d == limit)
            if dfs(pos+1, nextTight, path) {
                return true
            }
            path = path[:len(path)-1] // 回溯：撤销选择
        }
        return false
    }

    // 先尝试 m 位数字
    if dfs(0, true, []byte{}) {
        return ans
    }
    // 兜底：少一位，全填最大数字
    if m > 1 {
        path := make([]byte, m-1)
        for i := range path {
            path[i] = byte('0' + nums[len(nums)-1])
        }
        val, _ := strconv.Atoi(string(path))
        return val
    }
    return -1
}

    方法二：数字构造回溯（k = k - 1 技巧）#

    另一种更直观的回溯思路：不按位置，而是不断往末尾追加数字（path*10 + num），通过剪枝 path > k 来缩小搜索空间。

    核心技巧：先把 k 减 1，将「严格小于 k」转化为「≤ k-1」，这样终止条件从 < k 变成了 == k-1（可直接 return）。

    // 数字构造回溯 —— path*10+num 逐位拼接
// 更贴近"枚举所有可能的数字"的直觉
func findMaxNumberBuild(nums []int, k int) int {
    sort.Ints(nums) // 排序保证一致性，虽不减少搜索空间但是好习惯
    k = k - 1       // 核心技巧：严格小于 k → ≤ k-1
    if k < 0 {
        return -1
    }

    // 检查 0 是否在 nums 中（用于判断 path=0 是否合法）
    hasZero := false
    for _, num := range nums {
        if num == 0 {
            hasZero = true
            break
        }
    }

    ans := -1
    var backtrack func(path int)
    backtrack = func(path int) {
        // 剪枝：超过上限，停止搜索
        if path > k {
            return
        }
        // 恰好等于上限，直接就是最优解
        if path == k {
            ans = path
            return
        }
        // 更新当前最优（path=0 仅在 nums 含 0 时才合法）
        if path > ans && (path > 0 || hasZero) {
            ans = path
        }
        // 尝试往末尾追加每一个数字
        for _, num := range nums {
            // 跳过前导零：避免 0*10+0=0 造成无限递归
            if path == 0 && num == 0 {
                continue
            }
            // 注意：直接传表达式，不修改 path 本身
            backtrack(path*10 + num)
        }
    }

    backtrack(0)
    return ans
}

    易错点：

    1. path 不能修改后不恢复。错误写法：

      path = path*10 + num    // ❌ 改完不恢复
backtrack(path)         // 下轮循环用的还是改过的值

      正确写法是直接传表达式 backtrack(path*10 + num)，path 保持原值，回溯自然发生。

    2. 前导零导致无限递归。当 nums 包含 0 时，0*10+0 = 0，递归回到起点永不终止。用 if path == 0 && num == 0 { continue } 跳过。

    3. ans 初始值设为 -1，且 path=0 只在 nums 含 0 时才视为合法。否则 nums=[2], k=2 会错误返回 0 而非 -1。

    4. k = k - 1 边界。当 k 较小时（如 k=1），k-1=0，搜索空间很小。若 k=0，k-1=-1，直接返回 -1。

    5. 排序不减少搜索空间，但降序是好习惯。Build 方法的剪枝 path > k 对每个前缀的判定与遍历顺序无关——无论升序还是降序，访问的节点总数完全相同。但将 nums 降序排列有两个好处：① 更早找到较大的 ans，接近 k-1 的值会被优先探索；② 与贪心和 DFS 方法保持输入一致性（它们需要排序）。所以实际代码中建议先 sort.Ints(nums)。

    两种回溯方法对比#

    方法一：逐位 DFS方法二：数字构造
    思路按位决策，tight 标记是否受限不断追加数字，k-1 简化边界
    回溯方式path = append; ...; path = path[:len-1]backtrack(path*10+num) 自动回溯

    方法一是方法二的「压缩版」——省去了对不可能前缀的搜索。但方法二更直观地展示了回溯的本质：从空串出发，每次追加一个数字，不满足就回退。面试中两种都可以讲，先讲方法二建立直觉，再优化到方法一展示进阶。

    k = k - 1 能用于前两种方法吗？#

    不能。原因如下：

    1. 字符串位数会变化。 贪心降级和逐位 DFS 都依赖 k 的字符串表示来做逐位决策。k=100 时 s="100" 有 3 位，而 k-1=99 时 s="99" 只有 2 位。位数一变，整个降级点枚举逻辑就被打乱了——本来要找 3 位数中的最大值，结果变成了找 2 位数中的最大值，而 2 位数的情况已经在兜底逻辑中覆盖了。

    2. 比较方式根本不同。

    贪心 / 逐位 DFS数字构造（Build）
    比较对象逐位比较字符（s[p] vs digit）整体比较数值（path vs k）
    保证 < k 的方式构造保证：降级点选 < s[p] 的数字运行时剪枝：if path > k { return }
    k-1 的作用无——不需要数值比较有——把 < k 变成 ≤ k-1，可以直接 == 命中

    贪心算法中，候选数字 < k 由构造过程保证（降级点选了比 k[p] 小的数字），不需要事后用数值检查。k-1 在这里帮不上忙。

    3. 即使位数不变，收益也微乎其微。 当 k-1 和 k 位数相同时（比如 k=555 → 554），贪心算法里唯一的区别是把 largestLess < s[p] 改成 largestLess ≤ s'[p]。这相当于把 == 的情况从「继续匹配下一位」变成了「在当前位置终止并填 max」。结果一样，没有加速。

    一句话总结：k = k - 1 是专门为数值比较型回溯准备的工具，对于基于字符串逐位决策的方法不适用。
