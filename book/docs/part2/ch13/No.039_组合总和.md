## 39 组合总和-中等

题目：

给你一个 **无重复元素** 的整数数组 `candidates` 和一个目标整数 `target` ，找出 `candidates` 中可以使数字和为目标数 `target` 的 所有 **不同组合** ，并以列表形式返回。你可以按 **任意顺序** 返回这些组合。

`candidates` 中的 **同一个** 数字可以 **无限制重复被选取** 。如果至少一个数字的被选数量不同，则两种组合是不同的。 

对于给定的输入，保证和为 `target` 的不同组合数少于 `150` 个。



> **示例 1：**
>
> ```
> 输入：candidates = [2,3,6,7], target = 7
> 输出：[[2,2,3],[7]]
> 解释：
> 2 和 3 可以形成一组候选，2 + 2 + 3 = 7 。注意 2 可以使用多次。
> 7 也是一个候选， 7 = 7 。
> 仅有这两种组合。
> ```
>
> **示例 2：**
>
> ```
> 输入: candidates = [2,3,5], target = 8
> 输出: [[2,2,2,2],[2,3,3],[3,5]]
> ```
>
> **示例 3：**
>
> ```
> 输入: candidates = [2], target = 1
> 输出: []
> ```



分析：

这道题是回溯算法中最经典的代表作之一。理解这道题，就掌握了回溯算法的核心思想。

### 一、回溯算法的核心思想

回溯算法本质上是在**遍历一棵决策树**。想象你站在一个路口：

- **路径**（path）：你已经走过的路（已经做出的选择）
- **选择列表**（choices）：当前路口可以走的方向（还能选哪些数字）
- **结束条件**（terminal）：到达终点或走进死胡同（和等于 target / 和大于 target）

回溯算法做的就是：站在每个路口，依次尝试每一种选择；走到底之后，**撤销最后一步**，退回来尝试另一种选择。这「撤销」的动作，就是「回溯」名字的由来。

```
                 ┌─────────────┐
                 │  站在当前节点 │
                 └──────┬──────┘
                        │
                  ┌─────▼─────┐
                  │ 满足结束条件？│
                  └──┬──────┬──┘
                  是 │      │ 否
                     │      │
              ┌──────▼─┐    │
              │ 收集答案 │    │
              └────────┘    │
                             │
                      ┌──────▼──────┐
                      │ for 遍历选择列表 │
                      └──────┬──────┘
                             │
                      ┌──────▼──────┐
                      │   做出选择    │
                      │ path←add(x) │
                      └──────┬──────┘
                             │
                      ┌──────▼──────┐
                      │ 递归进入下一层 │
                      └──────┬──────┘
                             │
                      ┌──────▼──────┐
                      │ 撤销选择(回溯) │
                      │ path←remove()│
                      └─────────────┘
```

代码框架：

```go
func backtrack(路径, 选择列表) {
    if 满足结束条件 {
        result.add(路径)
        return
    }

    for 选择 := range 选择列表 {
        做出选择（将选择加入路径）
        backtrack(路径, 选择列表)  // 进入下一层决策
        撤销选择（将选择从路径移除）  // ← 这就是"回溯"
    }
}
```

### 二、本题的决策树剖析

以 `candidates = [2,3,6,7], target = 7` 为例，画出完整的决策树。

**关键规则**：
1. 数组**先排序**，保证候选集递增
2. 递归时传递当前索引 `idx`，**不回退**——避免产生 `[2,3,2]` 和 `[2,2,3]` 这样的重复组合
3. 因为元素可以**重复使用**，所以递归时传 `idx` 而不是 `idx+1`（对比：不可重复的题目传 `idx+1`）
4. 如果当前数字已经大于剩余目标值，**剪枝**（后续更大的数字也不可能选中）

下面是完整的决策树（`candidates = [2,3,6,7], target = 7`）：

```
                              ┌─────────────────────┐
                              │  []  target=7  idx=0 │
                              │  候选: [2, 3, 6, 7]  │
                              └──┬──┬──┬──┬─────────┘
                                 │  │  │  │
                   ┌─────────────┘  │  │  └────────────┐
                   │               │  │                │
              idx=0,选2        idx=1,选3          idx=3,选7
                   │               │                   │
         ┌─────────▼──────┐  ┌────▼─────┐      ┌──────▼──────┐
         │[2]  target=5   │  │[3] tar=4 │      │ [7]  tar=0  │
         │ 候选:[2,3,6,7] │  │候选:[3,6,7]│     │    ✓ 收集!   │
         └──┬──┬──┬───────┘  └──┬──┬──┘   │      └─────────────┘
            │  │  │             │  │       │
   ┌────────┘  │  └────┐    ┌───┘  │   idx=2,6>4
   │           │       │    │      │   剪枝!
 idx=0,选2  idx=1,选3  │  选3    选6
   │           │   剪枝!  │    tar=-2
   │           │  idx=2,6  │    死路
   │           │  >5,剪枝  │
   │           │           │
┌──▼────────┐ ┌▼─────────┐ ┌▼──────────┐
│[2,2]     │ │[2,3]     │ │[3,3]      │
│target=3  │ │target=2  │ │target=1    │
│候选:[2,3]│ │候选:[3,6] │ │候选:[3,6]  │
└──┬──┬────┘ └──┬──┬────┘ └──┬──┬─────┘
   │  │         │  │         │  │
  选2 选3      选3 选6>2    选3 选6>1
   │  │         │  剪枝    3>1 剪枝
   │  │         │         剪枝
┌──▼──────┐ ┌──▼───┐  ┌──▼──────┐
│[2,2,2]  │ │[2,2,3]│ │[2,3,3] │
│target=1 │ │tar=0  │ │tar=-1  │
│候选:[2] │ │ ✓收集! │ │ 死路   │
│2>1,剪枝 │ └───────┘ └────────┘
└─────────┘
```

**说明**：
- 🟢 绿色/✓ 表示找到合法组合
- 🔴 死路 / 剪枝 表示此路不通，直接返回
- 注意 `[2,3,2]` 不会出现，因为选了 3（idx=1）之后只能从 idx=1 开始继续选，不会再回到 idx=0 去选 2

### 三、逐步骤详细拆解

下面把递归调用的每一步都拆开来看：

> **初始化**：`candidates` 排序为 `[2, 3, 6, 7]`，调用 `backtrack(candidates, 0, 7, [])`

---

**第 1 步：`backtrack(nums, idx=0, target=7, path=[])`**

`idx=0`，进入 for 循环 `i=0..3`：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 0 | 2 | 2 ≤ 7 ✓ | path=[2], 递归: `backtrack(nums, 0, 5, [2])` |
| 1 | 3 | 3 ≤ 7 ✓ | path=[3], 递归: `backtrack(nums, 1, 4, [3])` |
| 2 | 6 | 6 ≤ 7 ✓ | path=[6], 递归: `backtrack(nums, 2, 1, [6])` |
| 3 | 7 | 7 ≤ 7 ✓ | path=[7], 递归: `backtrack(nums, 3, 0, [7])` → **target=0，收集 [7]!** |

---

**第 2 步（进入 i=0 的递归）：`backtrack(nums, idx=0, target=5, path=[2])`**

`idx=0`，进入 for 循环 `i=0..3`：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 0 | 2 | 2 ≤ 5 ✓ | path=[2,2], 递归: `backtrack(nums, 0, 3, [2,2])` |
| 1 | 3 | 3 ≤ 5 ✓ | path=[2,3], 递归: `backtrack(nums, 1, 2, [2,3])` |
| 2 | 6 | 6 > 5 ✗ | **break！** 6 已经大于 5，后面 7 更大，直接跳出循环 |

---

**第 3 步（进入 [2,2] 的递归）：`backtrack(nums, idx=0, target=3, path=[2,2])`**

`idx=0`，进入 for 循环 `i=0..3`：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 0 | 2 | 2 ≤ 3 ✓ | path=[2,2,2], 递归: `backtrack(nums, 0, 1, [2,2,2])` |
| 1 | 3 | 3 ≤ 3 ✓ | path=[2,2,3], 递归: `backtrack(nums, 1, 0, [2,2,3])` → **target=0，收集 [2,2,3]!** |
| 2 | 6 | 6 > 3 ✗ | break |

---

**第 4 步（进入 [2,2,2] 的递归）：`backtrack(nums, idx=0, target=1, path=[2,2,2])`**

`idx=0`，进入 for 循环：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 0 | 2 | 2 > 1 ✗ | **break！** 死路，直接返回 |

---

**第 5 步（返回 [2,2] 层，回溯，进入 i=1）：** 上面第 3 步的 i=1 已经走过并收集了 [2,2,3]，现在 for 循环结束，返回。

---

**第 6 步（回溯到 [2] 层，进入 i=1 的递归）：`backtrack(nums, idx=1, target=2, path=[2,3])`**

`idx=1`，进入 for 循环 `i=1..3`：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 1 | 3 | 3 > 2 ✗ | **break！** 死路，直接返回 |

注意：这里 `idx=1`，所以 i 从 1 开始——不会再去选 nums[0]=2，避免了 [2,3,2] 的出现。

---

**第 7 步（回溯到根层 []，进入 i=1 的递归）：`backtrack(nums, idx=1, target=4, path=[3])`**

`idx=1`，进入 for 循环 `i=1..3`：

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 1 | 3 | 3 ≤ 4 ✓ | path=[3,3], 递归: `backtrack(nums, 1, 1, [3,3])` |
| 2 | 6 | 6 > 4 ✗ | break |

---

**第 8 步（进入 [3,3] 的递归）：`backtrack(nums, idx=1, target=1, path=[3,3])`**

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 1 | 3 | 3 > 1 ✗ | break，死路 |

---

**第 9 步（回溯到根层 []，进入 i=2 的递归）：`backtrack(nums, idx=2, target=1, path=[6])`**

| i | nums[i] | 与 target 比较 | 操作 |
|---|---------|---------------|------|
| 2 | 6 | 6 > 1 ✗ | break，死路 |

---

**第 10 步（回溯到根层 []，进入 i=3 的递归）：** 已在第 1 步中收集 [7]。

---

**最终结果：`[[2,2,3], [7]]`** ✅

### 四、关键要点总结

#### 1. 为什么要排序？

排序有两个重要作用：

- **剪枝优化**：当 `nums[i] > target` 时，由于数组已排序，后续的 `nums[i+1], nums[i+2]...` 都更大，可以直接 `break` 跳出循环，大幅减少无效递归。
- **去重保证**：排序后配合 `idx` 参数，确保每个组合内部是非递减的（如 `[2,2,3]`），避免了 `[2,3,2]`、`[3,2,2]` 这类重复排列。

#### 2. 为什么递归时传 `i` 而不是 `i+1`？

```go
backtrack(nums, i, target-nums[i], temp)  // 传 i：元素可以无限制重复选取
backtrack(nums, i+1, target-nums[i], temp) // 传 i+1：每个元素只能选一次
```

这是本题与第 40 题（组合总和 II）最核心的区别。本题允许同一个数字无限次使用，所以递归时 `idx` 不变（= i），下次还能再选同一个数字。

#### 3. 剪枝的位置

```go
if nums[i] > target {
    break  // 不是 continue！因为排序后后面的都更大
}
```

这个剪枝是本题效率的关键。没有它，会有大量超过 target 的无意义递归。

#### 4. 为什么要 `copy` 一份结果？

```go
one := make([]int, len(temp))
copy(one, temp)
res = append(res, one)
```

因为 `temp` 这个切片在回溯过程中会被不断修改（append 和 slice 截断），如果直接 `append(res, temp)`，底层数组会被后续的回溯操作污染。必须拷贝一份独立的副本。

### 五、Go 语言实现

```go
// date 2023/12/26
func combinationSum(candidates []int, target int) [][]int {
    res := make([][]int, 0, 16)

    // 回溯函数定义
    // nums:  候选数组（已排序）
    // idx:   当前搜索的起始索引（保证组合非递减，避免重复）
    // target: 剩余需要凑的目标值
    // temp:  当前路径（已选数字）
    var backtrack func(nums []int, idx, target int, temp []int)
    backtrack = func(nums []int, idx, target int, temp []int) {
        // 终止条件：target <= 0
        if target <= 0 {
            if target == 0 {
                // 找到一个合法组合，拷贝并保存
                one := make([]int, len(temp))
                copy(one, temp)
                res = append(res, one)
            }
            return
        }

        // 遍历当前可选列表（从 idx 开始，不回退）
        for i := idx; i < len(nums); i++ {
            // 剪枝：当前数字大于剩余目标值，后面更大，直接跳出
            if nums[i] > target {
                break
            }

            // 做出选择：将 nums[i] 加入路径
            temp = append(temp, nums[i])

            // 递归：因为数字可以重复使用，所以传递 i 而不是 i+1
            backtrack(nums, i, target-nums[i], temp)

            // 撤销选择（回溯）：移除最后加入的数字
            temp = temp[:len(temp)-1]
        }
    }

    // 先排序——这是剪枝和去重的前提
    sort.Slice(candidates, func(i, j int) bool {
        return candidates[i] < candidates[j]
    })

    backtrack(candidates, 0, target, []int{})

    return res
}
```

### 六、复杂度分析

- **时间复杂度**：`O(n^(target/min))`，最坏情况下指数量级。设 $S$ 为 target 的值，每次至少减 1（$min=1$ 时），决策树深度可达 $S$，每层至多 $n$ 个分支，因此上界为 $O(n^S)$。实际上排序和剪枝会大幅削减搜索空间，题目保证合法组合数不超过 150，所以实际运行时间非常快。

- **空间复杂度**：`O(target/min)`，即递归栈的最大深度。当 `min(candidates)=1` 时，最深可递归 target 层；加上存储结果的空间 $O(K \times L)$，其中 $K$ 是组合数，$L$ 是组合的平均长度。
