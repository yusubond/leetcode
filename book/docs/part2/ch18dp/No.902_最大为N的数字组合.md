## 902 最大为 N的数字组合-困难

题目：

给定一个按 **非递减顺序** 排列的数字数组 `digits` 。你可以用任意次数 `digits[i]` 来写的数字。例如，如果 `digits = ['1','3','5']`，我们可以写数字，如 `'13'`, `'551'`, 和 `'1351315'`。

返回 *可以生成的小于或等于给定整数 `n` 的正整数的个数* 。



> **示例 1：**
>
> ```
> 输入：digits = ["1","3","5","7"], n = 100
> 输出：20
> 解释：
> 可写出的 20 个数字是：
> 1, 3, 5, 7, 11, 13, 15, 17, 31, 33, 35, 37, 51, 53, 55, 57, 71, 73, 75, 77.
> ```
>
> **示例 2：**
>
> ```
> 输入：digits = ["1","4","9"], n = 1000000000
> 输出：29523
> 解释：
> 可写出的 3^1 + 3^2 + 3^3 + 3^4 + 3^5 + 3^6 + 3^7 + 3^8 + 3^9 = 29523 个数字。
> ```
>
> **示例 3：**
>
> ```
> 输入：digits = ["7"], n = 8
> 输出：1
> ```



分析：

### 一、核心思路

这道题是经典的**数位 DP（Digit DP）** 问题。数位 DP 的核心思想是：将一个数字按位拆开，从高位到低位逐位决策，根据当前前缀是否"紧贴"上限来决定后续选择的自由度。

如果直接用回溯枚举所有可能的数字，n 最大可达 10^9，搜索空间是指数级的，必然超时。关键在于审题：题目只要求返回**个数**，不要求列出具体数字。

把问题拆成两个独立的部分：

**部分一：位数少于 n 的数字**

如果 n 有 m 位，那么所有 1 位、2 位、...、m−1 位的数字一定小于 n。对于长度为 L 的数字，每一位都可以从 digits 中任选，所以有 k^L 种（k = len(digits)）。

**部分二：位数等于 n 的数字**

从高位到低位逐位处理 n 的每一位数字。设 n 的字符串形式为 s，长度为 m，当前处理到第 i 位（0-indexed）：

- 统计 digits 中**严格小于** s[i] 的数字个数，记为 `less`。对于每个比 s[i] 小的数字放在第 i 位，后面 m−i−1 位可以任选 digits 中的数字，贡献 `less × k^(m−i−1)` 个。
- 然后检查 s[i] 是否**等于** digits 中的某个数字：
  - 如果在，说明可以继续匹配下去，进入下一位（i+1）。
  - 如果不在，说明无法构造出与 n 前缀相同的数字，直接返回当前累计结果。
- 如果顺利走完 n 的所有位（即 n 的每一位都在 digits 中），说明 n 本身也可以被构造出来，结果 +1。

### 二、数位 DP 的状态转移

数位 DP 的核心状态有两个：

- **tight（紧贴）**：当前前缀与 n 的前缀完全相等，后续位的选择受 n 对应位的限制。
- **free（自由）**：当前前缀已经小于 n 的前缀，后续位可以任选 digits 中的任意数字。

下面用决策树来可视化这两个状态的转移过程：

以 `digits = ["1","3","5"], n = 53` 为例，画出决策树：

```
                        ┌──────────────────┐
                        │   根节点（空）      │
                        │   统计所有 ≤53 的数  │
                        └────────┬─────────┘

                  1位数: 1,3,5 → 3^1 = 3 个

                      │  第0位: s[0] = '5'  │
                      │  digits中小于'5'的:  │
                      │  '1', '3' → less=2  │
                      └──────────┬──────────┘
                                 │
              ┌──────────────────┼──────────────────┐

**计数汇总**：
- 1位数：3^1 = 3
- 第0位选小于'5'的：less=2 × 3^1 = 6（即 1x 和 3x 各 3 个）
- 第0位选'5'后，第1位选小于'3'的：less=1 × 3^0 = 1（即 51）
- n 本身可以构造：+1（即 53）
- **总计：3 + 6 + 1 + 1 = 11**

验证：≤53 且由 {1,3,5} 组成的数字：
1位数：1, 3, 5（3个）
2位数：11, 13, 15, 31, 33, 35, 51, 53（8个）
共 11 个 ✓

### 三、逐步骤拆解

以 `digits = ["1","3","5","7"], n = 350` 为例，`s = "350"`, `m = 3`, `k = 4`。

---

**Step 1：位数少于 3 的数字**

| 位数 | 公式 | 个数 |
|------|------|------|
| 1 | k^1 = 4^1 | 4 |
| 2 | k^2 = 4^2 | 16 |

累计：4 + 16 = **20** 个。

---

**Step 2：位数等于 3，逐位处理 n = "350"**

**i=0，s[0] = '3'：**

- digits 中小于 '3' 的有：'1' → `less = 1`
- 贡献：1 × 4^2 = **16** 个（1xx，后面两位各 4 种选择 = 16 个）
- '3' 在 digits 中 ✓ → 继续

**i=1，s[1] = '5'：**

- digits 中小于 '5' 的有：'1', '3' → `less = 2`
- 贡献：2 × 4^1 = **8** 个（31x 和 33x，最后一位各 4 种选择）
- '5' 在 digits 中 ✓ → 继续

**i=2，s[2] = '0'：**

- digits 中小于 '0' 的：无 → `less = 0`
- 贡献：0 × 4^0 = **0** 个
- '0' 不在 digits 中 ✗ → **停止！**

---

**最终结果：20 + 16 + 8 + 0 = 44**

验证：≤350 且由 {1,3,5,7} 组成的数：
- 1位数(4) + 2位数(16) = 20
- 3位数 1xx：16 个（111,113,115,117,...177）
- 3位数 3xx 且 ≤350：
  - 31x：4 个（311,313,315,317）
  - 33x：4 个（331,333,335,337）
  - 35x：0 个（351>350）
  - 37x：0 个（371>350）
- 共：20 + 16 + 4 + 4 = 44 ✓

### 四、Go 语言实现

```go
// date 2025/06/24
func atMostNGivenDigitSet(digits []string, n int) int {
    s := strconv.Itoa(n)
    m := len(s)   // n 的位数
    k := len(digits)

    // 预处理：计算 k 的各个幂次
    // pow[i] = k^i
    pow := make([]int, m)
    pow[0] = 1
    for i := 1; i < m; i++ {
        pow[i] = pow[i-1] * k
    }

    // 第一部分：位数少于 m 的所有数字
    // 1位数 + 2位数 + ... + (m-1)位数
    ans := 0
    for i := 1; i < m; i++ {
        ans += pow[i] // pow[i] = k^i
    }

    // 第二部分：位数等于 m 的数字，逐位比较
    for i := 0; i < m; i++ {
        // 统计 digits 中小于 s[i] 的个数
        less := 0
        for j := 0; j < k; j++ {
            if digits[j][0] < s[i] {
                less++
            } else {
                break // digits 已排序，后面都 ≥ s[i]
            }
        }
        // 每个较小数字 + 后面任意填
        ans += less * pow[m-i-1]

        // 检查 s[i] 是否在 digits 中
        found := false
        for j := 0; j < k; j++ {
            if digits[j][0] == s[i] {
                found = true
                break
            }
        }
        if !found {
            return ans // 无法继续匹配
        }
    }

    // n 本身也可以被构造
    return ans + 1
}
```

**代码要点说明**：

1. **预处理幂次数组 `pow`**：避免重复计算 `k^(m-i-1)`，同时防止浮点精度问题（不使用 `math.Pow`）。

2. **利用 digits 已排序的特性**：在统计 `less` 时，一旦 `digits[j][0] >= s[i]` 就可以 `break`，因为后面都更大。

3. **提前返回**：如果 n 的某一位不在 digits 中，后面不可能构造出与 n 前缀匹配的数字，直接返回。

4. **最后 +1**：只有当 n 的每一位都能在 digits 中找到时，才会走到循环结束，此时 n 本身也是一个合法数字。

### 五、复杂度分析

- **时间复杂度**：O(m × k)，其中 m 是 n 的位数（≤10），k 是 digits 的长度（≤9）。由于 m ≤ 10 且 k ≤ 9，实际上是常数时间。

- **空间复杂度**：O(m)，即预处理的幂次数组大小。

### 六、关键要点总结

#### 1. 为什么用 DP 而不是回溯枚举？

回溯枚举每一个数字的复杂度是指数级的。n 最大为 10^9，如果 digits 有 9 个数字，合法的数字个数约为 4 亿级别，枚举必然超时。题目只要求**个数**，不需要列出具体数字——这正是 DP 的典型场景：把指数级的枚举压缩为多项式级的计数。

#### 2. 问题的拆解方式

```
总数 = 位数少于n的所有数字 + 位数等于n且≤n的数字
```

第一部分直接用幂次求和，第二部分逐位比较。这种「拆解 + 分类讨论」是许多计数问题的核心技巧。

#### 3. 数位 DP 的通用模板

这道题是经典的**数位 DP**（Digit DP）入门题。数位 DP 的核心思想就是逐位决策 + 状态转移：

- 状态一（tight）：当前前缀是否与 n 的前缀"紧贴"（相等）
- 状态二（free）：当前前缀已经小于 n 的前缀，后面任选

本题的 `less * k^(剩余位数)` 对应的是「从 tight 转到 free」的批量计数。如果追求更通用的解法，可以写成 DP 形式：

```go
// 数位 DP 版本（更通用，可处理更多约束）
func atMostNGivenDigitSet_DP(digits []string, n int) int {
    s := strconv.Itoa(n)
    m := len(s)
    k := len(digits)

    // dp[i][tight]
    // tight=0: 前i位已经小于n的前i位，后面任选
    // tight=1: 前i位等于n的前i位
    dp := make([][2]int, m+1)
    dp[0][1] = 1 // 空前缀与n的前0位相等

    for i := 0; i < m; i++ {
        for j := 0; j < k; j++ {
            d := digits[j][0]
            if d < s[i] {
                // 选一个较小的数字：之前tight的状态转成free
                dp[i+1][0] += dp[i][0] + dp[i][1]
            } else if d == s[i] {
                // 选相等的数字：tight保持tight，free保持free
                dp[i+1][0] += dp[i][0]
                dp[i+1][1] += dp[i][1]
            } else {
                // 选一个较大的数字：只有free状态才能选
                dp[i+1][0] += dp[i][0]
            }
        }
    }

    // 位数等于m的结果
    ans := dp[m][0] + dp[m][1] - 1 // 减去空前缀

    // 加上位数少于m的
    for i := 1; i < m; i++ {
        p := 1
        for j := 0; j < i; j++ {
            p *= k
        }
        ans += p
    }

    return ans
}
```

两种写法本质相同，第一种更直观，第二种（数位 DP）更容易扩展到有额外约束的场景（如"数字不能重复"、"相邻位有约束"等）。

#### 4. 为什么 digits 是字符串数组？

输入 `digits` 的类型是 `[]string` 而非 `[]byte`，这是 LeetCode 的题目设定。代码中用 `digits[j][0]` 获取字符，与 `s[i]`（byte）直接比较，无需类型转换。
